# Changelog

## Unreleased

- Review advisories closed (T49, S9, S15, S16): terminal focus no longer treats paste brackets or terminal replies (DA, cursor, OSC, DCS, kitty) as the user being present, and only attaches when the wrap really took effect; a throwing delivery in the deferral re-run is no longer an unhandled rejection; the Python env refuses a non-absolute home, does not reuse an mlx-audio other than the pinned one, and rebuilds (`--clear`) a leftover venv whose interpreter is broken or older than 3.10; the doctor's audio probe runs only for a verified runtime at an absolute path with a minimal environment.
- First-start setup and `/speak doctor` (T44, S15): one confirmation (also `/speak` → «Instalar todo») lists the missing runtime, Piper `es_MX` and, on Apple Silicon, a gentle-speak Python env (`<home>/python` via uv or `python3 -m venv` ≥ 3.10, pinned `mlx-audio==0.4.4`, recorded in `python.json`) and the Qwen Base model with their sizes, then installs them one by one in the background (a failure stops only its component; VoiceDesign is never included; ffmpeg is only detected and hinted, never installed; setting `setupOffer: "declined"` remembers a decline); `/speak doctor` (or «Doctor») reports 14 read-only checks as ✓/✗/– with fix hints, including the shared service pid, version and build without connecting to it, and ends with an optional spoken test.
- The shared Qwen service now carries a build id (T50, S13, L98): the first 12 hex chars of a sha256 over the exact bytes of `speak-qwen-service.mjs` and `speak-qwen-worker.py`, sent in the handshake as `build`. A client whose scripts differ replaces a running service with the same package version and protocol (a pre-T50 service with no `build` counts as different), through the existing graceful path: the old service finishes everything already queued, then exits. The 30 s restart rate limit keeps two builds from taking turns; older and newer package ordering is unchanged. This fixes a stale service surviving code changes and failing every custom-voice request.
- Focus now comes from the terminal's own focus reports (T46, S16, S9): gentle-speak observes pi-tui's `\x1b[I`/`\x1b[O` on the live fullscreen TUI (reads a private pi-tui method, restored on shutdown or `/reload`, self-disables if it is missing), typing implies focus (60 s when the terminal sends no events), a deferred result is spoken as soon as you focus the window without waiting for the poll, Herdr and the frontmost app remain the fallback, and off macOS a known Herdr answer no longer needs the frontmost check.
- The 7 personal Qwen reference voices (`qwen-*`) leave the public catalog and no WAV is shipped: Qwen voices are now only your own (`custom:<id>`, «Crear voz propia…» / «Importar mi grabación…»); at session start, once, an existing install (`~/.gentle-speak/voices/qwen3/` with a valid manifest) is converted into custom voices with the same label, transcript and sha256 (WAVs copied, nothing deleted) and `voice: qwen-<name>` is mapped to `custom:<name>` in the terminal's and Dot's settings; an old `qwen-*` setting without a migrated voice still loads and falls back like a missing voice; custom voices now need only the Python record `~/.gentle-speak/python.json` (the old manifest's python is still read), and the shared service accepts only `voices/custom/<id>/reference.wav` (T45, S15).
- Own voices (T42, S14): `/speak` → «Crear voz propia…» (VoiceDesign 1.7B from a text description, after a separate confirmed model download that shows its size), «Importar mi grabación…» (explicit consent, validated PCM WAV 3-30 s) and «Borrar voz propia…» store sha256-verified voices in `~/.gentle-speak/voices/custom/<id>/`, listed as `Propia · <label>` (`custom:<id>`) in the voice menu, `cycleVoice` and Dot's voice picker; the shared service accepts their `reference.wav`; a missing or invalid one falls back like a missing Qwen voice.
- Connecting Gentle Dot now accepts the terminal's git source for gentle-speak (`git:<host>/<owner>/gentle-speak[.git][@ref]` or `https://…/gentle-speak[.git][@ref]`), copied verbatim; other repository names, credentials, query/fragment, ssh/file forms stay refused, and connect/disconnect detect git entries (T41, S12).
- The shared Qwen service now stays loaded while any session is open (each session keeps one presence connection, no per-speech idle close) and, after the last session leaves, waits `qwenIdleMinutes` from that disconnect (default now 10; `/speak` → «Mantener Qwen tras cerrar la última sesión») before unloading Python and exiting; prerelease versions order per semver and the `ps` timing test asserts progress instead of a stall bound (T40, S13).
- Shared Qwen service review fixes (T39, S13): CR, CRLF, VT and FF in text are accepted and normalized instead of rejected (other control characters still are); the service now exits after the one S13 idle timeout with no client (README, comments and code agree; no separate 30 minute default); a newer client replaces an older service but an older one never does (it uses a protocol-compatible newer service, else a local worker), with replacements rate-limited to one per 30 s so two versions no longer ping-pong; the pid check (`ps`) is asynchronous and bounded.
- One shared local Qwen service (`scripts/speak-qwen-service.mjs`, unix socket `~/.gentle-speak/qwen.sock`, 0600 in a 0700 dir) now serves every terminal session and Gentle Dot with a single Python worker, loading the model once; it starts on demand, prioritizes the voice-lock holder over speculation, owns the S13 idle close, restarts after a package update or a stale socket, falls back to a per-session worker when it cannot run, and `/speak` → `Detener servicio Qwen` stops it (T38, S13).
- The warm Qwen worker (about 2.6 GB per session) is now closed after `qwenIdleMinutes` of inactivity (default 5, `/speak` → `Liberar Qwen tras inactividad`, 1-60 or never) and respawns transparently on the next speech, also after an external kill; no fallback, no error (S13).
- Qwen voices send each streamed part as soon as it is synthesized, so the first audio starts after about 1.5 s instead of waiting for a whole 250-character group.
- Added a catalog of seven Qwen3-TTS reference voices (`qwen-*`, model `mlx-community/Qwen3-TTS-12Hz-0.6B-Base-bf16`), a sha256-verified installer into `~/.gentle-speak/voices/qwen3/`, and a rebindable `cycleVoice` key (default `ctrl+alt+n`). Existing settings files stay valid; Piper `es_MX`/`es_ES` and the default voice are unchanged. Engine routing and menus follow separately.
- Qwen voices now speak: a persistent Python synth worker (`scripts/speak-qwen-worker.py`, schema `gentle.speak.qwen/v1`, mlx-audio, offline) streams sentence-group WAV chunks to a new `play` message of the Node audio worker. Piper behaviour and the existing `speak` message are unchanged; a Qwen voice that is not installed is refused with a clear error and nothing is spawned.
- Added the SPEAK status row (state, active voice, configured toggle and cycle keys) in Gentle Shell's INTEGRATIONS section, the `cycleVoice` shortcut that advances to the next installed voice, and a `/speak` voice menu generated from the catalog (label, id, installed state) with a `Key: cycleVoice` rebind. The row is set only in the interactive parent TUI and cleared on shutdown or reload.
- Qwen speech: the utterance timeout no longer counts playback; readiness (180 s) and a per-event synthesis idle timeout (120 s) replace it, a failed Qwen worker spawn is reported cleanly, and every Qwen failure path is now covered by tests.
- Added an opt-in `copySpeech` setting (default off, existing settings files stay valid) and a `/speak` entry `Toggle speak copied selection`: text you select and copy in this Gentle Shell is spoken with the current voice. macOS and the fullscreen TUI are required; copies in other apps or panes, and concealed/password copies, are skipped. The SPEAK row shows `· copia` while it is on.
- Playback now opens the output device's own default config and resamples in-process, so it never asks the device to change its sample rate (fixes `Sample rate update timed out` on Bluetooth headsets whose rate differs from the voice). A playback failure now reports its cause: `Audio playback failed: <cause>.` (bounded to 120 characters, no paths).
- Qwen replay: late `chunk`/`done`/`error` messages of a cancelled or superseded request are ignored, so replaying while a Qwen utterance is running speaks the new text instead of failing with `Invalid Qwen worker response.`; messages with never-issued ids are still rejected.
- Several sessions: one cross-process voice lock under `~/.gentle-speak/` so sessions never overlap; automatic speech and the `speak` tool speak at once only when the pane is focused (terminal frontmost + Herdr), otherwise keep the latest result until focus, and when focus is unknown speak in turn prefixed with the project name. Hardening: `HERDR_BIN_PATH` must be an absolute `.../herdr`, lock release/reclaim re-verify the owner after the rename, and a refused device default config falls back to the supported-config search once.
- Speculation never slows first audio: a sentence still being synthesized at settle is kept when it continues the final text, its parts play as they arrive (`prepare(...).handle`, `speakPrepared({ inflight })`), and the remainder is synthesized after it; a non-matching one is aborted and deleted.
- Qwen voices speak faster: while the answer is being written, completed sentences are synthesized ahead (parent TUI, auto-speak on, mode other than `summary`; Piper is unchanged), and at settle the matching audio plays at once and only the rest is synthesized; nothing plays before the answer is final, and mismatches, tool-call turns, stop, toggle off, voice change and shutdown delete the prepared files.
- Libraries for speculative speech: `lib/speak-speculative.ts` plans which completed sentences of a streaming answer to synthesize ahead (one synthesis at a time, at most 500 characters ahead, exact-prefix match at settle, everything else deleted), and `createQwenSpeech` gains `prepare` (synthesize WAVs without playing, cancellable), `speakPrepared` (play them, then synthesize the remainder) and `discard`. A prepare never runs together with a speak: it waits for one, and a speak cancels it.
- Playback no longer aborts on non-fatal stream errors (buffer underrun/overrun, device rerouted, real-time scheduling refused): it plays to the end, bounded by the utterance timeout and a 50-glitch cap; other stream errors still fail with their cause.
- Added the macOS `Mac` voice (`/usr/bin/say`, text on stdin, no download) as an extra voice and as a fallback when the selected Piper or Qwen voice is not installed or fails (`macVoice`, `macFallback`, `/speak` → `Mac voice` / `Toggle Mac fallback`; notified once per session; never on cancel or stop).
- Added Gentle Dot support (S12): opt-in `dotSpeech` makes Dot's root RPC session speak with a `Dot: ` prefix and no focus deferral, a one-time offer in the terminal (`dotOffer`) and `/speak` → `Conectar/Desconectar Gentle Dot` add or remove gentle-speak in Dot's `settings.json` `packages` after a backup; existing settings files stay valid.
- Gentle Dot now has its own settings (S12, T34): Dot reads `<dotHome>/.gentle-speak/speak-settings.json` and speaks only when its own `enabled` is set, while runtime, models, voices and the voice lock stay in the real `~/.gentle-speak`; connect seeds it from the terminal's settings, and `/speak` → `Gentle Dot` replaces `Hablar en Gentle Dot` (terminal `dotSpeech` is now ignored).
- Review fixes (T36): connecting Gentle Dot writes only a validated package source (an absolute existing dir holding `gentle-speak`, or an `npm:gentle-speak[@version]` spec; otherwise it refuses with a notice and touches nothing); Dot's `<dotHome>/.gentle-speak` ends 0700 when it is ours; the Gentle Dot submenu acts on a fresh read after you choose instead of a stale snapshot; a per-app `$HOME` (Dot) wins over an injected speak home for settings; the Mac voice probe is shared and a failed or empty re-list keeps the last good list.

## 0.1.0 - 2026-11-08 (local candidate)

- Added opt-in Spanish speech for final questions and usable results, with `all` and model-assisted `summary` modes.
- Added `/speak` configuration, manual `speak` tool, rebindable shortcuts, and explicit verified downloads of separate converted voice and native runtime artifacts.
- Restricted playback to interactive parent TUI sessions; stop, reload, and shutdown discard pending speech.
- Added package metadata and a representative speech illustration for eventual gallery discovery.

Publication is pending independent installer/archive audit and live Pi integration verification. No public repository, gallery listing, or npm release is claimed.
- The SPEAK row now always shows the copy-speech state with its key (`· copia ○ ctrl+alt+c` / `· copia ●`), and a new rebindable `toggleCopy` key (default `ctrl+alt+c`, `/speak` → `Key: toggleCopy`) toggles it through the same path as `/speak` → `Toggle speak copied selection`. Existing settings files without `toggleCopy` still load with a free default.
- Voice lock hardening: a stale lock is reclaimed only while holding a separate `voice.reclaim` mutex (itself recovered when its holder died), the owner release never renames the lock path, `acquire` never throws a raw fs error, and shutdown/reload closes the lock (pending acquires rejected, a held lock released once). Focus probes (Herdr and frontmost app) now run concurrently, each bounded at 700 ms; a probe that times out means focus unknown. `HERDR_BIN_PATH` must also be an existing executable regular file, otherwise `herdr` from PATH is used.
- Gentle Dot: inside its engine `$HOME` is overridden, so gentle-speak now resolves `~/.gentle-speak`, Dot's default engine home and `~` in package sources from the account's real home (`lib/speak-home.ts`), and the Qwen Python worker is started with that `HOME` (`-E -P` kept). The Mac voice list is time-bounded (1.5 s) and an empty or failed list is retried instead of cached.
